# Upstream

This template is built on the [fullstackhero .NET starter kit](https://github.com/fullstackhero/dotnet-starter-kit), whose features and fixes land on its `main` branch between releases. We follow every commit on their `main`: the platform team reviews each one and syncs it into this repository's `main`, or records why not. We also refactor the template ourselves, so a commit is synced by porting it, not by merging their branch.

**Synced up to:** [`44412b2`](https://github.com/fullstackhero/dotnet-starter-kit/commit/44412b2) (2026-06-19), the release `10.0.0` this template is built on. The 79 commits after it are in section 3.

## 1. Procedure

1. **Check for new commits** every two weeks, and at once when GitHub or NuGet reports an advisory that fullstackhero fixes. Open `https://github.com/fullstackhero/dotnet-starter-kit/compare/<synced up to>...main`, or, in a clone of their repository, run `git log --reverse --oneline <synced up to>..origin/main`.
2. **Add a row per new commit** to section 3, oldest first, with the commit, its date, its subject and the list of its changes, from its message and its diff, and set its status to Pending. A merge commit gets a row of its own that points to the rows of the commits it merges.
3. **Decide each row** in a PR that reviews the changes, and set its status:
   - **Synced:** the change is ported. Our PR goes in the last column.
   - **Covered:** we already have the change, or our own version of it. Name where.
   - **Skipped:** we don't want it, for example because we replaced that part. Give the reason.
   - **Not applicable:** it only touches what this template removed (section 2).
4. **Port a change** in a branch from our `main`, in one of two ways:
   - **By patch,** where our code still matches theirs: `git -C <their clone> format-patch -1 <commit> --stdout`, with the paths renamed as in section 2, then `git am -3`. Then resolve the conflicts by hand.
   - **By hand,** where we refactored that part: write the same fix or feature in our code.

   One PR may port several commits. Name each upstream commit in the PR description and in the commit message (`Sync fullstackhero <commit>: <subject>`). The PR passes `ci / ci` like any other, and a migration from upstream keeps its name and order.
5. **Move "Synced up to"** to the newest commit that is no longer Pending, when every row before it is decided.
6. **Existing product repositories:** for each synced change, the platform team decides whether a product repository gets a PR too, and names those PRs in the row.

A security fix goes first: an upstream commit that fixes a vulnerability, a CVE or a NuGet or npm advisory is synced before the other pending rows.
